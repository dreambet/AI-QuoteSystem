## 第 1 周 · 项目初始化与数据基础设施

### 关键事项
- 后端项目初始化（任务1）：Express 服务器，监听 3001
- 前端项目初始化（任务2）：Create React App，3000 端口，proxy 到后端
- 数据存储与 Quote 模型（任务3）：SQLite 单表 + JSON 列

### 开发思路
- **前后端分离单仓库**：`backend/` 与 `frontend/` 同级，便于联调与整体交付。
- **数据层"单表 + JSON 列"**：报价对象含多个嵌套结构（`calculation`、`aiReview`、`manualReview` 等），用单张 `quotes` 表 + TEXT 列存 JSON，避免多表 JOIN，读写简单。
- **应用层 ID 生成**：`Quote.id = Date.now().toString(36) + 随机串`，不依赖数据库自增，便于跨环境迁移与导入导出。
- **前端 CRA + proxy**：`frontend/package.json` 配 `proxy: http://localhost:3001`，前端用相对路径 `/api/...`，规避跨域与硬编码后端地址。

### 开发过程
1. 后端：`package.json` 装 express/cors/sqlite3/multer/pdfkit，nodemon 热重载；`app.js` 注册 cors + json 中间件；`server.js` 监听 3001。
2. 前端：CRA 结构，react-router-dom v6，`public/index.html` + `#root` 挂载。
3. 数据库：`db.js` 连接 SQLite，`init-db.js` 建 `quotes` 表；`models/Quote.js` 封装 `create/findAll/findById/update/_parseRow`——`update` 时把 object 序列化为 JSON 字符串，`_parseRow` 读取时反序列化。
4. **引入自动迁移**：`db.js` 与 `init-db.js` 对比 `PRAGMA table_info(quotes)` 与"期望列"清单，缺失列执行 `ALTER TABLE ADD COLUMN`，实现无破坏性的字段演进。

### 阶段产出
后端可启动且 `/health` 返回 ok；前端可启动显示首页；`quotes` 表与 Quote CRUD 模型就绪。

## 第 2 周 · 后端核心 API 与报价计算引擎

### 关键事项
- 报价 API 路由（任务4）：RESTful CRUD
- 报价计算引擎（任务6）：`QuoteCalculator`

### 开发思路
- **计算引擎确定性、可解释**：材料成本（体积×密度×单价）+ 五道工序工时 + 管理费 15% + 利润 20%，价格/密度/精度系数均为硬编码常量表，不引入随机或 ML，保证同输入同输出，便于审核与对账。
- **工时与体积挂钩**：单工序工时 = √体积 × timeFactor × 精度系数 / 10，用平方根让大件工时增长放缓，贴合实际加工经验。
- **路由与模型分层**：`routes/quotes.js` 只做参数校验与状态流转，计算逻辑全部下沉到 `services/QuoteCalculator.js`。

### 开发过程
1. `quotes.js`：实现 `POST/GET/GET:id/PUT` 四个端点，挂载 `/api/quotes`。
2. 新增 `POST /:id/calculate`：取 quote → `QuoteCalculator.calculate` → 回写 `calculation` 并置 `status=calculated`。
3. `QuoteCalculator` 常量表：
   - `MATERIAL_PRICES`：钢 15 / 铝 25 / 铜 45 / 不锈钢 35（元/kg）
   - `MATERIAL_DENSITIES`：7.85 / 2.7 / 8.96 / 7.93（g/cm³）
   - `PRECISION_FACTORS`：低 1.0 / 中 1.2 / 高 1.5 / 极高 2.0
   - `PROCESSES`：下料/粗加工/精加工/表面处理/质检，timeFactor 0.1/0.3/0.4/0.1/0.1，时薪 60/80/100/50/40
4. 体积计算：`diameter>0` 走圆柱 πr²h/1000，否则长方体 lwh/1000，默认值 100/50/20。
5. 输出结构：`materialCost/laborCost/equipmentCost/overheadCost/profit/total/unitPrice` + `breakdown`（体积、重量、工序明细），供前端展示。

### 阶段产出
报价 CRUD + 计算接口可用，`curl` 触发 `/calculate` 返回完整成本明细。

## 第 3 周 · AI 审核与报价单生成

### 关键事项
- AI 审核服务（任务7）：`AIReviewer` 规则引擎
- 人工审核与报价单生成（任务8）：`QuoteGenerator`（PDFKit）

### 开发思路
- **两个"AI"职责分离**：`AIReviewer` 是纯规则引擎（不调外部 API），快速、零成本、可解释；真正的 LLM 调用留到第 5 周 `DeepSeekService`，避免审核环节强依赖网络与 Key。
- **状态机驱动流转**：`draft → calculated → ai_reviewed → manually_reviewed → finalized`（及 `rejected`），每个端点写回对应 JSON 并推进 `status`。
- **PDF 服务端生成**：用 PDFKit 在后端拼装明细 + 审核意见，`GET /:id/export` 用 `res.download` 下发，无需前端打印库。

### 开发过程
1. `AIReviewer.review`：规则包括总价 <100 或 >100000 警告、材料占比 >60% 建议优化、批量 >100 建议折扣、铜/不锈钢提醒确认行情；返回 `{status, comments, suggestions}`。
2. `POST /:id/ai-review`：调用 `review`，回写 `aiReview`，`status=ai_reviewed`。
3. `QuoteGenerator.generatePDF`：PDFDocument 输出标题/报价号/零件信息/成本明细/AI 审核意见/人工审核/总计，流式写入 `uploads/quote-{id}.pdf`。
4. `POST /:id/manual-review`：接收 `status/comments`，回写 `manualReview`，`approved→finalized` 否则 `manually_reviewed`。
5. `GET /:id/export`：生成 PDF 并 `res.download`。

### 阶段产出
报价可走"计算 → AI 审核 → 人工审核 → 导出 PDF"完整链路，状态机闭环。

## 第 4 周 · 前端界面与图纸上传

### 关键事项
- 报价创建表单（任务5）：`QuoteForm` + `api/quotes.js`
- 报价详情与列表页（任务9）：`QuoteDetail` + `QuoteList`
- 图纸上传（任务10）：`upload.js` + multer

### 开发思路
- **API 集中管理**：`src/api/quotes.js` 统一封装 axios 调用，因 CRA proxy 全部用相对路径 `/api/...`，组件不直接碰 URL。
- **页面按创建流程分**：手动（`/quotes/new` → `QuoteForm`）与详情（`/quotes/:id`），`QuoteList` 作首页（`/`）。
- **上传与业务路由存储规则一致**：`routes/upload.js` 与 `routes/quotes.js` 的 multer 都用 `uploads/` + 时间戳随机文件名，改动两处保持同步。

### 开发过程
1. `api/quotes.js`：`quoteApi`（create/getAll/getById/update/calculate/aiReview/manualReview/export）。
2. `QuoteForm`：受控表单，材料/精度下拉，提交后跳详情页；后扩展图纸上传（file input + `uploadApi`，上传后存 `drawingPath`）。
3. `QuoteList`：列表 + 状态映射（draft/calculated/ai_reviewed/...），链接到详情。
4. `QuoteDetail`：按状态条件渲染"计算 / AI 审核 / 人工审核 / 导出"按钮与结果卡片。
5. `upload.js`：multer diskStorage，`filename = Date.now() + 随机 + 扩展名`，`POST /api/upload/drawing` 返回 `filename`。
6. `App.js` 路由：`/`、`/quotes`、`/quotes/new`、`/quotes/:id`。

### 易踩的坑（已记录到 CLAUDE.md）
- `QuoteDetail.js`（旧）与 `QuoteDetail.jsx`（新）并存，`App.js` 实际导入 `.jsx`；改 `.js` 不生效。
- 新页面用 `.jsx`，旧页面用 `.js`，`App.js` 的 import 显式带扩展名。

### 阶段产出
前端可完成"新建 → 上传图纸 → 计算 → 审核 → 导出"全流程交互。

## 第 5 周 · AI 智能报价增强与系统集成发布

### 关键事项
- `DeepSeekService`：真 LLM 调用（图纸多模态视觉分析 + 报价建议）
- `CADParserService`：DXF / DWG / STEP 三格式解析
- `AIQuoteCreation.jsx`：5 步向导 + three.js 3D 预览
- 端到端集成测试与发布（`feat: publish AI quote system`）

### 开发思路
- **真假 AI 分工**：图纸参数提取与报价建议走 DeepSeek（`deepseek-chat` + `response_format: json_object`），无 Key 或调用失败时回退 fallback，系统仍可运行（优雅降级）。
- **CAD 解析进程内完成、零外部依赖**：DXF 用 `dxf-parser`；DWG 用 `dwgdxf`（WebAssembly）进程内转 DXF，无需安装 AutoCAD/ODA；STEP 用 `occt-import-js` 读三角网格。
- **2D 图纸推断 3D**：DXF/DWG 产出"参数化模型规格"（最大闭合轮廓 outline + 内部圆孔 holes），前端 three.js 拉伸成 3D 并标注特征；STEP 直接给三角网格，缓存为 `uploads/models/{id}.json`，由 `GET /:id/3d-model` 提供。

### 开发过程
1. `DeepSeekService`：`analyzeDrawingWithVision`（图片多模态）、`analyzeQuoteWithAI`（chat 报价分析），均 `json_object`；失败走 `fallbackQuoteAnalysis` 固定模板。
2. `CADParserService`：`parseDXF/parseDWG/parseSTEP`；`_buildParametricModelSpec` 选最大闭合多段线为 outline、圈内圆为 holes；`_serializeMesh` 序列化 STEP 网格。
3. `routes/quotes.js` 扩展：
   - `POST /:id/analyze-drawing`：按扩展名分流 CAD/图片，CAD 解析或 AI 视觉，结果写回 `drawingAnalysis` 并同步 `length/width/height/diameter/material` 等。
   - `POST /:id/ai-quote`：DeepSeek 分析 + 内部重算 `calculation`，`status=ai_quoted`。
   - `GET /:id/3d-model`：返回缓存的 STEP 网格。
4. `AIQuoteCreation.jsx`：`@react-three/fiber` + `@react-three/drei` 渲染 3D 模型与特征标记；5 步向导：上传 → 分析 → 确认参数 → 报价 → 建议。
5. `QuoteDetail.jsx` 重构为当前生效版本（替换旧 `.js`）。
6. 集成测试：完整跑通 AI 路径，提交 `feat: publish AI quote system`（07-31）。

### 易踩的坑（已记录到 CLAUDE.md）
- `dwgdxf` 默认 wasm 路径在 Windows 下失效，需在构造函数显式将 `wasmBase` 指向已安装包的 `wasm/` 目录。
- 新增数据库字段需同步改三处：`db.js` 与 `init-db.js` 的 CREATE TABLE + 期望列清单、`Quote` 模型 `create/update/_parseRow`。

### 阶段产出
AI 智能报价路径上线：上传图纸 → AI/CAD 提取参数 → 3D 预览 → 报价 → AI 建议；系统具备手动与 AI 双创建流程，可对外演示。

## 风险与注意事项
- `rebuild-db` 会清空全部报价数据，生产环境禁用；仅 `init-db` 安全。
- `backend/uploads/` 与 `backend/data/` 不入库，需在服务器上持久化并定期备份。
- DeepSeek API 按 token 计费，大量图片建议先压缩；无 Key 时 AI 功能降级，核心报价流程不受影响。
- CAD 解析依赖 wasm/occt，部署环境需保证 Node 能加载 WebAssembly 模块。
